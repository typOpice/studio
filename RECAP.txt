STUDIO PROJECT RECAP
Last updated: 2026-09-26


WHAT THIS IS

A Roblox Studio style 3D game maker for macOS, written in Swift and Metal.
There are two apps: Studio.app (the editor) and StudioClient.app (the player / game client).
Scripts are written in Luau (the main language, like Roblox) or Wren (a second language that gets new features later).
Physics is Jolt Physics. Luau, Wren and Jolt are included as source code in the project.
Everything is one Swift package. Xcode 27 is installed now (Swift 6.4), but the project doesn't need it: it still builds with just the command line tools.


HOW TO CHECK THAT EVERYTHING STILL WORKS

Run all the automatic checks:  swift run StudioApp --selftest
They must all pass before any change counts as done (2023 checks at the end of this session, all passing).
Build the two apps:  ./make_app.sh release
AGENTS.md explains how the code is organised and the rules that are easy to break. Read it first.
README.md is the guide for people using the apps.
CLAUDE.md is a short note for the AI assistant.


WHAT WAS BUILT BEFORE THIS SESSION

The editor: parts (block, sphere, cylinder, wedge), move/scale/rotate tools with snapping, undo and redo, saving and opening scenes, saving and inserting models.
Scripting in Luau with a Roblox-like API, and in Wren. Custom shaders in Metal for parts and for the whole screen.
The player character: a Humanoid driven by scripts, a default ControlScript and Health script, StarterPlayer settings, respawning.
Touched and TouchEnded events, CanCollide and CanTouch.
A better looking avatar with walk, jump, fall, fly and death animations.
An Animation Editor with a timeline and keyframes, and AnimationTrack for scripts.
Lighting: conventional shadows and ray traced lighting, point lights, sky, fog, time of day.
Models and Folders (the Explorer is a tree) and CFrame.
Real physics for unanchored parts using Jolt.
Welds and joints: hinge, ball socket, rope, spring, slider, with motors and servos. Squashed spheres and cylinders collide with their true shape.

7. Local network (LAN) multiplayer, first stage:
   In the client, "Host on your network" advertises the game on the local network using Bonjour.
   Another Mac on the same network sees it under "Join a game" without typing an address.
   Joining sends the player's name and colours to the host. The host sends back its scene, and the joiner plays that scene.
   Both sides see a list of who is in the game, and notice when someone leaves or the host stops.
   A player on a different version is turned away with a message.
   Checked for real over the network connection on this machine (loopback), and Bonjour advertising and finding were checked by hand.
   UPDATE: players now see each other. Every player sends where their character is, which way it faces, its pose and whether it is dead, 20 times a second. The host passes everyone's on to everyone. Each client draws the other players in their own colours with their name above their head, gliding smoothly between updates. The protocol version is now 2, so both copies must be the new build.
   UPDATE 2: the two worlds are now one. The host runs the scene's scripts and physics and sends what changes (parts moving, falling or made by scripts, lighting, shader settings) 20 times a second. A joining player no longer runs the scene's scripts or physics; they see the host's. Someone joining mid-game gets the world as it is then.
   Players now bump into each other, and parts land on and stop against every player. A map can turn player-to-player collisions off: in Studio, select StarterPlayer and untick "Players collide".
   Bugs found and fixed while doing this (they affected single player too): parts dropped on a player who was moving fell straight through them (a collision filter in the Jolt glue code); and with two or more players, a moving part could freeze because its new position was never read back.
   UPDATE 3: the host's scripts now see every player. Players:GetPlayers lists everyone, Players.PlayerAdded and PlayerRemoving fire, each player has their own Character and CharacterAdded, and GetPlayerFromCharacter works. A joined player touching a part fires Touched on the host, so kill bricks, coins, speed pads and teleporters work for everyone. When a host script changes a joined player's Health, WalkSpeed or position, the change is sent to that player's game, which runs their character; the host then reads back what that player reports.
   NOT DONE YET: a joined player nudges crates rather than pushing them properly, and host scripts cannot play animations on other players' characters.

10. Screen GUI and chat.

   GUI: scripts can make ScreenGui, Frame, TextLabel, TextButton, TextBox, UICorner and UIPadding, place them with UDim2 and AnchorPoint, and put them in player.PlayerGui.    Over the network, a player's message goes to the host, which sends it to everyone else under the name that player joined with. The protocol version is now 5, so all copies must be the new build.
   Tested alone and with a host and a joiner over the network connection on this machine: typing / and a message on one side shows it on the other, both ways.
   New files: Sources/StudioKit/Play/Gui.swift, Sources/StudioKit/Play/PlayController+Gui.swift, Sources/StudioKit/UI/GuiLayer.swift, Sources/StudioKit/Scripting/LuauLibrary/09-Gui.swift, Sources/StudioKit/GuiSelfTest.swift.

16. The task library finished, 2026-09-24.
   task.defer now runs in the same frame, once the code running now is done (it used to wait for the next frame). A deferred function can defer more; a script that defers itself forever doesn't freeze the game.
   task.cancel now works wherever the thread is waiting, including on an event's :Wait(). Before, the event firing later printed a "cannot resume dead coroutine" error. It refuses, with a clear message, to cancel the thread that is running, and cancelling a finished thread does nothing.
   task.wait, spawn, delay, defer and cancel check their arguments and give Roblox's error messages (for example "invalid argument #1 to 'wait' (number expected, got string)").
   The old globals now behave like Roblox's: wait() waits at least 1/30 s and returns the game time as a second value, delay() is never sooner than 1/30 s, and spawn() starts its function a frame later instead of immediately.
   task.synchronize and task.desynchronize exist. There are no Actors, so everything runs in series and they carry straight on.
   Threads due at the same moment now wake in the order they went to sleep, as in Roblox.
   Tested alone and on a host and a joined player.
   Fixed after: the chat window sat 84 points down, below the old built-in panel in the corner; with that panel gone it left a gap. It now sits 16 points in from the top-left corner.

17. MeshParts (3D models), 2026-09-25.
   3D models can be imported like pictures and sounds: OBJ, STL, PLY and USD (USDA, USDC, USDZ), the formats macOS reads itself. FBX and glTF are not supported; export them as OBJ or USD first.
   Home > Mesh (or right-click a model in Assets > Insert MeshPart) puts a MeshPart on the ground at the model's own size, or 8 studs across if the model is far too big or small. Size stretches it like any part.
   Properties has a Mesh section: the model (MeshId), one picture wrapped on it using the model's texture coordinates (TextureID, tinted by the part colour), CollisionFidelity and Reset Size.
   CollisionFidelity works like Roblox: Hull (the default, shrink-wrapped), Box, or Precise (the real triangles, so you can walk through an arch or drop things into a cup). Precise only applies while the part is anchored; a moving Precise part collides as its hull. Clicking always hits the real shape.
   Luau: Instance.new("MeshPart"), MeshId, TextureID, CollisionFidelity (Enum.CollisionFidelity), MeshSize (read only), ClassName "MeshPart", IsA. Wren has no MeshPart yet.
   Saved Models take their 3D models and pictures with them. Joined players get the models with the world.
   Drawn with shadows and ray tracing like other parts. Meshes are drawn two-sided.
   Tested alone and with a host and a joined player (the joiner walks through a Precise arch on their own machine and sees a MeshPart a host script makes).
   New files: Model/MeshGeometry.swift, Model/TriangleSet.swift, Model/SceneModel+Mesh.swift, UI/MeshUI.swift, MeshSelfTest.swift.

Tables, Vector3s, colours, parts, players and characters all go across. Works alone, in Studio's play test and in network games.

   Leaderstats: a Folder called leaderstats in a Player shows on a new leaderboard, top right (Tab hides it). It's an ordinary StarterGui ScreenGui (PlayerList) with its own LocalScript. New scenes have it; old scenes that kept the default HUD get it when opened.

   Code completion knows all of it. Luau only; Wren has none of it.
   Tested alone and with a host and a joined player, including the README's examples.
   Also corrected the notes that said there is no Xcode: Xcode 27 is installed, but the project still builds without it.
   New files: Model/DataObjects.swift, Scripting/ScriptRuntime+Data.swift, Scripting/LuauLibrary/15-Data.swift (the entry points are now part 16), Play/PlayController+Remotes.swift, UI/DataObjectsUI.swift, RemotesSelfTest.swift.

22. Calmer code suggestions, 2026-09-26.
   The script editor's suggestion list was too pushy: it wrote its first guess into the code as soon as it opened, and took Return, so typing end, then or do and pressing Return needed Return twice. It also suggested things while you were naming a new variable, and put Enum before end.
   Now nothing goes into the code until you choose. Tab puts in the highlighted suggestion. Return does only after you have picked one with the up and down arrows; otherwise Return is a new line. Esc closes the list, and Option-Esc opens it when you want it.
   It opens at once after a dot or colon, and for a word only once two letters are typed and you pause.
   It stays away when the word is already typed in full, when you are naming something (local x, for i, a function's name and parameters), in the middle of a word, after the dot in a number such as 0.5, and in comments and strings.
   Better order: matches in the case you typed come first (en gives end before Enum), then your script's own locals, then keywords, globals and libraries.
   The list is new: a small dark panel under the word, with a letter for each kind (p property, f function, v variable, T type, k keyword), the type on the right, and a line saying which keys to use. It serves Luau, Wren and shaders.
   New file: UI/CompletionList.swift.

23. Suggestions for require and ModuleScripts, 2026-09-26.
   Typing require( now lists every ModuleScript in the place, each written as the path from the script you are in: script.Parent.Helper for one beside it, otherwise through your own local ReplicatedStorage = game:GetService(...) if the script has one, or through game:GetService. Tab puts in the whole path and the closing bracket.
   The suggestions know what is really in the scene: ReplicatedStorage. lists what is in it, and so do workspace.Tower., script.Parent. and a Folder. Inside WaitForChild(" the names are suggested too, spaces and all, and the string and the call are closed for you. Inside require( only things that lead to a module are shown.
   After local Utils = require(...), Utils. lists what the module returns: its functions (with their parameters) and its values (with what they are: number, string, table, Vector3...), and Utils: lists its methods. Tables inside it work too (Utils.colours.). For a class module, an object made with Enemy.new(...) offers the class's methods and its self. fields.
   The module is read from its code, not run. The usual shapes are understood: local M = {} with M.x = ..., function M.x(...) and function M:x(...), then return M; or return { ... }.
   Also: the variable being declared on a line is no longer suggested on that same line.
   Luau only. Tested with a sample scene, a scene built in Studio, and Adventure Island's own modules.
   New files: Editor/LuauScene.swift, Editor/LuauModuleShape.swift.

24. Suggestions for GetService, 2026-09-26.
   Typing game:GetService(" lists every service. The one named like the variable you are declaring comes first (local TweenService = game:GetService(" puts TweenService at the top), and services the script already has go to the bottom. Tab puts in the name and closes the string and the bracket.
   Right after game:GetService( (before the quote) the list opens too, and puts the quotes in for you.
   LogService was missing from the suggestions and is now there. A test runs every suggested service through the real game:GetService, so the list can't offer one that doesn't exist.
